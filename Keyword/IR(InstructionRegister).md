# IR(Instruction Register)
>**IR(명령 레지스터, Instruction Register)**은 CPU 내부에 있는 핵심 제어 레지스터 중 하나로, **"메모리(RAM)에서 막 읽어와서 지금 바로 실행하려는 명령어를 임시로 보관하는 저장 장치"**입니다. \ 
이전에 다루었던 **PC(프로그램 카운터)**가 다음에 가져올 명령어의 **'주소(나침반)'**를 가리킨다면, IR은 그 주소에서 실제로 꺼내온 **'명령어 본체(보따리)'**를 담고 있는 장소입니다.
### 💡 실생활 예시
>요리사의 레시피 북: 요리사가 요리책을 보며 순서대로 요리를 합니다. **'다음 요리 단계가 적힌 페이지 번호'**는 PC입니다. \
그 페이지를 펼쳐서 **'현재 가리키고 있는 구체적인 조리법 문장("당근을 썰어라")'**을 머릿속에 기억해 두고 행동에 옮기는 순간, 그 문장이 저장된 기억 공간이 바로 IR입니다. 
### ⚙️ CPU 명령어 사이클에서 IR의 핵심 역할
>CPU가 하나의 명령을 처리하는 4단계 과정(인출 ➡️ 해독 ➡️ 실행 ➡️ 저장)에서 IR은 중간 가교 역할을 완벽하게 수행합니다. 
```
text
 [ 메모리 (RAM) ] ──(인출)──► [ 명령 레지스터 (IR) ] ──(해독)──► [ 제어장치 (CU) ] ──► (실행)
  주소 안의 실제 명령어          현재 실행할 명령 보관           제어 신호 생성 및 실행
```
- 인출 (Fetch)
    >CPU 제어장치가 PC에 적힌 주소를 보고 메모리에서 명령어를 읽어옵니다. 이 읽어온 명령어 데이터가 IR에 저장됩니다 [1].
- 해독 (Decode)
    >명령어 해독기(Decoder)가 IR에 저장된 바이너리 코드를 분석합니다. \
    명령어는 보통 '무엇을 할 것인가(연산 코드, Op-Code)'와 '대상이 누구인가(오퍼랜드, Operand)'로 나뉘는데, 이를 분리하여 해석합니다.
- 실행 (Execute)
    >해독된 결과에 따라 CPU 내부의 연산장치(ALU)가 계산을 수행하거나 제어장치가 신호를 보냅니다. 
### 🔍 연쇄 과정 예시: PC와 IR의 상호작용 
>메모리 100번지에 ADD A, B (A와 B를 더하라)라는 명령어가 들어있다고 가정해 보겠습니다.
- 시작: PC의 값은 100입니다.
- Fetch: CPU가 메모리 100번지를 조회하여 ADD A, B라는 명령어를 가져와 IR에 넣습니다.
- PC 증가: 명령어를 안전하게 IR에 담았으므로, PC는 자동으로 다음 주소인 101로 증가합니다 [1].
- Decode: 제어장치가 IR에 있는 ADD A, B를 분석하여 '더하기 연산(ADD)'임을 알아챕니다.
- Execute: ALU가 A와 B를 더하는 연산을 실제로 수행합니다. 
### 🚀 개발자 관점에서의 이해
>우리가 C#이나 C++ 같은 고수준 언어로 코드를 작성하면, 컴파일러가 이를 기계어(0과 1로 이루어진 바이너리)로 변환합니다.\
유니티에서 transform.Translate(Vector3.forward); 코드를 한 줄 실행하는 것도, CPU 레벨로 내려가면 수많은 메모리 주소 이동과 연산 명령어로 쪼개집니다.\
디버깅 툴을 사용해 소스 코드가 아닌 **어셈블리 코드(Disassembly View)**를 열었을 때, MOV, ADD, PUSH 같은 명령어 한 줄 한 줄이 CPU 구동 시 순서대로 IR에 탑재되어 실행되는 실제 명령어 유닛입니다.
