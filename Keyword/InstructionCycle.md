# 명령어 사이클
>명령어 사이클(Instruction Cycle)은 CPU가 메모리로부터 프로그램을 구성하는 명령어를 하나씩 가져와서 실행하는 전체적인 반복 과정을 말합니다.\
컴퓨터가 켜져 있는 동안 CPU는 이 사이클을 무한히 반복하며 작동합니다.
### 🔄 명령어 사이클의 4가지 핵심 단계
>명령어 사이클은 크게 4가지 단계로 쪼개어 진행됩니다. 앞서 공부하신 주소·데이터·제어 버스와 디코더가 여기서 모두 사용됩니다.
```
[ 1. 인출 (Fetch) ] ──> [ 2. 해독 (Decode) ]
        ▲                         │
        │                         ▼
[ 4. 인터럽트 (Interrupt) ] <── [ 3. 실행 (Execute) ]
```
1. 인출 단계 (Fetch Cycle)
    - 역할: 메모리에서 명령어를 CPU로 가져오는 단계입니다.
    - 동작: 주소 버스를 통해 메모리 위치를 지정하고, 제어 버스로 읽기 신호를 보내면, 메모리에 있던 명령어가 데이터 버스를 타고 CPU 내부의 레지스터(IR)로 들어옵니다.
2. 해독 단계 (Decode Cycle)
    - 역할: 가져온 명령어가 무슨 뜻인지 분석하는 단계입니다.
    - 동작: CPU 내부의 디코더(Decoder)가 명령어의 이진수 코드를 해독하여, 이것이 더하기(+)인지, 빼기(-)인지, 혹은 데이터를 저장하라는 뜻인지 알아냅니다.
3. 실행 단계 (Execute Cycle)
    - 역할: 해독된 명령어대로 실제 연산을 수행하는 단계입니다.
    - 동작: ALU(산술논리연산장치)를 통해 계산을 하거나, 다른 메모리 주소에서 데이터를 읽고 쓰는 등의 제어 신호를 보냅니다.
4. 간접/인터럽트 단계 (Indirect / Interrupt Cycle)
    - 역할: 예외 상황 처리 및 다음 명령어 준비 단계입니다.
    - 동작: 실행 도중 키보드 입력이나 오류 같은 인터럽트 제어 신호가 들어왔는지 확인하고, 문제가 없다면 다음 명령어의 주소를 가리키도록 준비합니다.
### 💡 버스와 디코더의 연결고리 총정리
>지금까지 질문하신 개념들이 명령어 사이클 안에서 어떻게 유기적으로 맞물리는지 한눈에 보여드릴게요.
- 주소 버스: 인출 단계에서 가져올 명령어의 주소를 보낼 때 사용
- 데이터 버스: 인출 단계에서 해당 명령어를 CPU로 실어 나를 때 사용
- 제어 버스: 메모리에 읽기/쓰기 신호를 보내고 인터럽트를 확인할 때 사용
- 디코더: 해독 단계에서 가져온 명령어가 무엇인지 쪼개어 분석할 때 사용
