# 인터럽터 사이클
인터럽트 사이클(Interrupt Cycle)은 CPU가 명령어를 실행하는 도중 외부에 예기치 못한 상황(정전, 하드웨어 오류, 입출력 완료 등)이 발생했을 때, 수행 중이던 프로그램을 잠시 중단하고 처리 요청을 검사하는 단계입니다.

핵심 요약
정의: 실행 사이클을 마친 CPU가 다음 명령어를 인출하기 전, 인터럽트 요청 여부를 확인하고 처리하는 과정입니다.
목적: 현재 실행 중인 프로그램의 상태(복귀 주소 등)를 안전하게 보관하고, 인터럽트 서비스 루틴(ISR)으로 제어를 넘깁니다.
특징: 인터럽트 처리가 끝나면 중단되었던 원래 프로그램의 다음 위치로 정확히 돌아와야 합니다.

인터럽트 사이클의 마이크로 연산 (Micro-operation)
인터럽트가 발생하면 CPU는 현재 PC(프로그램 카운터)에 있는 복귀 주소를 메모리의 특정 공간(주로 스택 또는 0번지)에 저장하고, 인터럽트 처리 프로그램의 시작 주소를 PC에 로드합니다.

아래는 일반적으로 스택(Stack)을 사용하거나 특정 메모리 주소(예: 0번지)에 복귀 주소를 저장할 때의 흐름입니다:
$$t_0 : \text{MBR} \leftarrow \text{PC}$$복귀 주소(현재 PC 값)를 메모리에 쓰기 위해 메모리 버퍼 레지스터(MBR)로 보냅니다.
\(t_1 : \text{MAR} \leftarrow \text{SP(또는 특정 주소)}, \quad \text{PC} \leftarrow \text{인터럽트 서비스 루틴의 시작 주소}\)복귀 주소를 저장할 주소(스택 포인터 SP 등)를 MAR에 지정합니다.
동시에 PC에는 다음에 실행할 인터럽트 처리 프로그램의 시작 주소를 적재합니다.
\(t_2 : \text{M[MAR]} \leftarrow \text{MBR}, \quad \text{SP} \leftarrow \text{SP} - 1\)MBR에 있던 원래 복귀 주소를 메모리에 최종 저장하고, 스택 포인터를 감소(혹은 증가)시켜 다음 저장을 준비합니다.

전체 명령어 사이클 흐름에서의 인터럽트인터럽트 사이클은 항상 실행 사이클이 끝난 직후에만 수행 여부를 판별합니다.
```
[인출 사이클] ──> [간접 사이클] ──> [실행 사이클] ──> [인터럽트 사이클] (요청이 있을 때만 진입)
     ▲                                   │ (요청 처리 완료 후)
     └───────────────────────────────────┘
```
인터럽트 사이클을 마치면 PC에는 인터럽트 서비스 루틴의 주소가 들어가 있으므로, CPU는 자연스럽게 다시 인출 사이클로 돌아가 인터럽트 처리 명령어를 가져오게 됩니다.
