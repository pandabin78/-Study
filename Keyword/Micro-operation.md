# 인터럽터 사이클
>인터럽트 사이클(Interrupt Cycle)은 CPU가 원래 수행 중이던 프로그램의 실행을 잠시 중단하고, 외부나 내부에서 발생한 인터럽트 요청을 처리하기 위해 제어를 이동하는 일련의 과정입니다. \
CPU의 전체 명령어 사이클(Instruction Cycle) 중 실행 사이클이 끝난 후 인터럽트 발생 여부를 확인할 때 진입하게 됩니다.

### 📌 명령어 사이클 내에서의 위치
>CPU는 보통 아래와 같은 주기를 반복하며 명령어를 처리합니다.
- 인출 사이클 (Fetch) -> 간접 사이클 (Indirect) -> 실행 사이클 (Execute) -> 인터럽트 사이클 (Interrupt)
- CPU는 하나의 명령어를 끝낼 때마다 항상 인터럽트 요구 신호가 들어왔는지 검사합니다.
- 인터럽트가 요청되어 있고 인터럽트 플래그가 활성화(가능) 상태라면 즉시 인터럽트 사이클로 진입합니다.

### ⚙️ 인터럽트 사이클의 주요 동작 (하드웨어 단계)
>인터럽트 사이클이 시작되면 CPU는 인터럽트 서비스 루틴(ISR)으로 안전하게 이동하기 위해 내부 레지스터를 조작합니다. 보통 3개의 클록(또는 마이크로 오퍼레이션) 단계로 수행됩니다
1. $t_0 : MBR \rightarrow PC$
    >1단계 (복귀 주소 백업 준비): 현재 프로그램 카운터(PC)에 저장된 복귀 주소(다음에 실행할 명령어 주소)를 임시로 메모리 버퍼 레지스터(MBR)로 옮깁니다.
2. $t_1 : MAR \leftarrow SP,\; PC \leftarrow \text{ISR의 시작 주소}$
    >2단계 (저장 위치 지정 및 ISR 주소 로드): 주소를 저장할 스택 포인터(SP)를 지정하고, PC에는 새롭게 실행할 인터럽트 서비스 루틴(ISR)의 시작 주소를 입력합니다.
3. $t_2 : M[\text{MAR}] \leftarrow MBR$
    >3단계 (메모리 저장): MBR에 보관 중이던 기존 복귀 주소를 실제 스택 메모리에 물리적으로 저장(Push)합니다.

### 🔄 전체 인터럽트 처리 흐름 (요약)
1. 인터럽트 요청: 
    >입출력 장치나 타이머 등에서 CPU로 신호를 보냅니다.
2. 신호 검사: 
    >CPU가 현재 수행 중인 실행 사이클을 마치고 신호를 확인합니다.
3. 콘텍스트 저장 (인터럽트 사이클): 
    >현재 PC의 내용을 스택에 안전하게 대피시킵니다.
4. ISR 실행: 
    >PC가 복제된 ISR 주소로 이동하여 인터럽트 처리 프로그램을 실행합니다.
5. 기존 프로그램 복귀: 
    >ISR 끝에 도달하면 스택에 보관했던 복귀 주소를 복원(Pop)하여 중단되었던 지점부터 다시 실행을 이어갑니다.
