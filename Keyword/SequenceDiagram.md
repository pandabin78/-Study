# 시퀀스 다이어그램
>시퀀스 다이어그램(Sequence Diagram)은 시스템의 동적 구조를 표현하는 대표적인 UML 다이어그램입니다. \
[1] 특정 유즈케이스가 실행될 때 객체들이 시간 순서에 따라 어떻게 메시지를 주고받으며 상호작용하는지를 시각적으로 보여줍니다. \
이전에 다룬 클래스 다이어그램이 시스템의 '정적인 뼈대(구조)'를 보여준다면, 시퀀스 다이어그램은 그 뼈대들이 '실제 살아 움직이는 흐름(과정)'을 보여줍니다. 
### 🧱 1. 시퀀스 다이어그램의 4대 핵심 구성 요소
- 객체(Object, 🔲)
    >상호작용에 참여하는 주체입니다. 사각형 안에 객체명:클래스명 형태로 표기합니다.
- 생명선(Lifeline, ┆)
    >객체 아래로 뻗어 나가는 점선입니다. 해당 객체가 메모리에 존재하는 시간의 흐름을 뜻합니다.
- 활성 상자(Activation Box, █)
    >생명선 위에 그려지는 긴 직사각형입니다. 해당 객체가 현재 어떤 메서드를 실행하며 '일하고 있는 상태'임을 나타냅니다.
- 메시지(Message, ──►)
    >객체 간에 데이터를 주고받거나 메서드를 호출하는 화살표입니다. 위에서 아래로 갈수록 시간이 흐름을 의미합니다. 
### 🎮 2. 유니티(Unity) 게임 시스템으로 보는 예시
>플레이어가 적(Monster)을 공격하고, 적이 데미지를 입어 사망한 뒤 UI가 업데이트되는 과정을 시퀀스 다이어그램으로 시각화한 모습입니다.
```text
 👤Player            ⚔️Weapon           👹Monster            🖥️UI
    │                  │                  │                  │
    │ ─── 1. Use() ──> │                  │                  │
    │                  │ ── 2. Attack ──> │                  │
    │                  │    (Raycast)     │                  │
    │                  │                  │ ── 3. Damage ──> │
    │                  │                  │    (스스로 연산)  │
    │                  │                  │                  │
    │                  │                  │ ── 4. Die() ───> │
    │                  │                  │                  │
    │ <───────────────────────────────────────────────────── │ 5. ShowVictory()
    │                  │                  │                  │ (유저에게 연출)
```
### 🔗 3. 메시지(Message)의 4가지 종류와 표현법
>다이어그램에서 화살표의 모양은 호출 방식의 특성을 반영합니다.
1. 동기 메시지 (Synchronous Message, ──►)
    - 설명: 메서드를 호출한 뒤, 그 작업이 끝날 때까지 호출한 쪽이 다른 일을 하지 않고 기다리는 일반적인 함수 호출입니다.
    - 표현: 속이 찬 삼각형 화살표 실선을 사용합니다. 
2. 비동기 메시지 (Asynchronous Message, ───▻)
    - 설명: 호출한 뒤 상대방의 작업 완료를 기다리지 않고 바로 자신의 다음 코드를 실행하는 방식입니다. (예: 유니티 Coroutine, async/await, 네트워크 패킷 전송)
    - 표현: 선으로 된 화살표 실선을 사용합니다. 
3. 반환 메시지 (Return Message, ◄┈┈┈) 
    - 설명: 호출된 메서드가 작업을 끝내고 결과를 돌려주는 값입니다. (활성 상자가 끝나는 지점)
    - 표현: 선으로 된 화살표 점선을 사용하며, 화살표 위에 return value를 적기도 합니다. 
4. 자체 메시지 (Self-Message, ↻)
    - 설명: 객체가 자기 자신의 메서드를 내부적으로 호출할 때 사용합니다.
    - 표현: 자기 자신의 생명선으로 돌아오는 U자형 화살표를 사용합니다. 
### 🔄 4. 복잡한 흐름을 제어하는 구조 요소 (Combined Fragments)
>조건문(if-else)이나 반복문(loop) 같은 제어 흐름은 다이어그램에 사각형 상자(Alt, Loop 등)를 둘러싸서 표현합니다.
- Alt (Alternatives)
    >if-else 조건문을 의미합니다. 상자를 가로 점선으로 나누어 조건에 따라 실행되는 영역을 구별합니다.
- Loop
    >for, while 반복문을 의미합니다. 특정 조건 동안 상자 안의 메시지 교환이 반복됨을 나타냅니다.
- Opt (Option)
    >if 조건문처럼 조건이 참일 때만 실행되고, 거짓이면 아무것도 하지 않는 선택적 상황을 뜻합니다. 
### 🚀 시퀀스 다이어그램을 그리면 얻는 효과
- 실행 흐름의 시각화
    >코드가 얽혀있을 때 어떤 순서로 함수가 맞물려 돌아가는지 직관적으로 파악할 수 있습니다.
- 코드 스멜과 결합도 발견
    >특정 객체 혼자 너무 많은 메시지를 주고받는 병목 현상이 보이거나, 왔다 갔다 하는 화살표가 지나치게 많다면 '강한 결합도'나 '기능 편애' 스멜이 나고 있다는 증거이므로 설계 단계에서 리팩토링 방향을 잡을 수 있습니다.
