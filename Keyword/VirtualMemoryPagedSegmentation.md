# 가상메모리 페이지드 세그멘테이션
> 페이지드 세그멘테이션(Paged Segmentation)은 가상메모리 관리 기볍 중 하나로, 세그멘테이션의 논리적 장점과 페이징의 물리적 장점을 결합한 혼용 기법입니다. 프로그램을 의미 있는 단위(세그먼트)로 나누되, 각각의 게그면트를 다시 고정된 크기(페이지)로 쪼개어 물리 메모리에 적재합니다.

### ?? 왜 두 기법을 합쳤을까요?
> 기존의 단일 기법들은 명확한 한계를 가지고 있었습니다. 두 기법의 단점을 서로 보완하기 위해 탄생 했습니다.

- 페이징(Paging) 
    > 메모리를 고정 크기로 나누어 외부 단편화가 없습니다. 하지만 코드가 섰여 있어 공유나 보안(권한 부여)등 논리적인 관리가 어렵습니다.
- 세그멘테이션(Segmentation)
    > 코드/데이터/스택 등 의미 단위로 나누어 보안과 공유가 쉽습니다.\
    하지만 크기가 제각각이라 메모리 사이사이에 빈 공간이 생기는 외부 단편화가 발생합니다.
- 페이지드 세그멘테이션
    > 외부 단편화 문제를 해결하면서(페이징의 장점), 동시에 논리적 단위로 보호 및 공유를 수행(세그멘테이션의 장점)합니다.

### ??? 작동 원리 및 주소 변환
> 사용자나 CPU가 바라보는 가상 주소는 다음과 같은 단계를 거쳐 실제 물리 주소로 반환됩니다.\
주소 변환을 위해 세그먼트 테이블과 페이지 테이블을 모두 거치게 됩니다.

```
[가상 주소: 세그먼트 번호(s) + 페이지 번호(p) + 변위/오프셋(d)]
             ↓
     1. 세그먼트 테이블 검색 ──> 해당 세그먼트의 페이지 테이블 시작 주소 획득
             ↓
     2. 페이지 테이블 검색 ────> 물리 메모리의 프레임 번호(f) 획득
             ↓
[물리 주소: 프레임 번호(f) + 변위/오프셋(d)]
```

1. 가상 주소 구조
    > CPU는 주소를 [세그먼트 번호(s), 페이지 번호(p), 변위(d)] 형태로 인식합니다.
2. 1차 변환(세그먼트 테이블)
    > 세그먼트 번호(s)를 이용해 세그먼트 테이블로 갑니다.\
    여기에는 기준 주소 대신 해당 세그먼트를 구성하는 '페이지 테이블의 시작 주소'가 들어있습니다.
3. 2차 변환(페이지 테이블)
    > 찾은 페이지 테이블에서 페이지 번호(p)를 이용해 실제 물리 메모리의 위치인 프레임 번호(f)를 알아냅니다.
4. 최종 물리 주소
    > 프레임 번호(f)와 처음의 변위(d)를 결합하여 실제 메모리 주소에 접근합니다.

### 장점과 단점 비교

| 구분 | 장점 | 단점 |
| --- | --- | --- |
| 페이징 | 외부 단편화 해결 | 내부 단편화 가능성 논리적 보호/공유 복잡 |
| 세그멘테이션 | 논리적 구조 명확 공유 및 보안 우수 | 외부 단편화 심함 메모리 할당 알고리즘 복잡 |
| 페이지드 세그멘테이션 | 외부 단편화 완벽 해결 세그먼트 단위 보안/공유 가능 | 주소 변환이 2배로 복잡함 테이블 유지를 위한 메모리 낭비 |

- 내부 단편화(Internal Fragmentation) 문제
    > 페이지드 세그멘테이션에서도 세그먼트의 마지막 조각이 페이지 크기보다 작으면 내부 단편화가 여전히 미세하게 발생할 수 있습니다.
- 속도 저하 보완
    > 메모리를 두 번이나 참조해야 하므로 속도가 느려질 수 있지만, 하드웨어 캐시 장치인 TLB(Translation Lookaside Buffer)를 사용하여 변환 속도를 획기적으로 가속합니다.
