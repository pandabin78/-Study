# 가상메모리 세그먼테이션
>가상메모리 세그먼테이션(Segmentation)은 프로그램을 고정된 크기가 아니라, 코드(Code), 데이터(Data), 스택(Stack), 힙(Heap) 등 논리적인 단위(의미 단위)인 세그먼트(Segment)로 나누어 메모리에 배치하는 기법입니다.

### ?? 세그먼테이션의 핵심 개념: 논리적 분할
>사용자나 컴파일러 관점에서 프로그램을 바라보는 방식과 유사하게 메모리를 나눕니다.

- 세그먼트 (Segment): 함수, 객체, 전역 변수, 스택 등 의미 있는 논리적 블록입니다. 각 블록은 저마다 크기가 다릅니다 (가변 크기).
- 기본 구조: 프로그램은 여러 개의 세그먼트로 구성되며, 각 세그먼트는 고유한 번호와 크기 정보를 가집니다.

### ?? 주소 변환 매커니즘 (Address Translation)
>CPU가 생성하는 가상 주소는 세그먼트 테이블(Segment Table)을 거쳐 물리 주소로 변환됩니다. 가변 크기를 다루기 때문에 테이블의 구조가 페이징과 다릅니다.

1. 세그먼트 번호 (s): 접근하려는 세그먼트의 고유 번호입니다.
1. 변위/오프셋 (d): 해당 세그먼트 시작 지점으로부터의 거리입니다.

#### [변환 및 검증 과정]

1. CPU가 가상 주소 (s, d)를 요청합니다.
1. 세그먼트 테이블에서 s번째 항목을 조회합니다. 이 항목은 두 가지 정보를 담고 있습니다.
    1. 기준 주소 (Base): 물리 메모리에서 해당 세그먼트가 시작되는 위치
    1. 한계치 (Limit): 해당 세그먼트의 실제 크기
1. 크기 검증: 오프셋 d가 세그먼트 크기(Limit)보다 큰지 확인합니다. 만약 d > Limit이면 메모리 침범 에러(Segment Fault)를 발생시킵니다.
1. 검증을 통과하면 Base + d를 계산하여 실제 물리 주소를 찾아갑니다.

### ?? 세그먼테이션의 장점과 단점
- 장점 (공유와 보호의 용이성):
    - 메모리 보호: 세그먼트별로 읽기/쓰기/실행 권한을 부여하기 쉽습니다. (예: 코드 세그먼트는 '읽기/실행'만 가능하게 설정하여 해킹 방지)
    - 메모리 공유: 여러 프로세스가 같은 함수나 라이브러리를 사용할 때, 해당 세그먼트만 공유 주소로 지정하면 되므로 효율적입니다.
    - 내부 단편화 해결: 프로세스가 필요한 크기만큼 딱 맞춰 메모리를 할당하므로 내부 단편화가 전혀 없습니다.
- 단점 (외부 단편화 발생):
    - 세그먼트들의 크기가 제각각이기 때문에, 메모리에 적재되고 해제되는 과정이 반복되면 중간중간 짜투리 공간이 생기는 외부 단편화(External Fragmentation)가 심하게 발생합니다.
    - 이를 해결하기 위해 메모리를 재배치하는 압축(Compaction) 작업이 필요해 시스템 부하가 커질 수 있습니다.

### ?? 현대 운영체제의 선택: 페이징-세그먼테이션 혼용 기법
>현대 운영체제(Windows, Linux 등)는 두 장점을 모두 취하기 위해 세그먼테이션과 페이징을 조합하여 사용합니다.

- 프로그램을 논리 단위(세그먼트)로 먼저 나눈 뒤, 보안과 공유 성능을 챙깁니다.
- 나눈 세그먼트를 다시 고정 크기(페이지)로 쪼개어 물리 메모리에 할당함으로써 외부 단편화 문제를 완벽히 해결합니다.
