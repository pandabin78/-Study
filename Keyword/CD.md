# 클래스 다이어그램
>클래스 다이어그램(Class Diagram)은 시스템의 정적 구조를 표현하는 가장 대표적인 UML 다이어그램입니다. \
시스템을 구성하는 클래스들의 내부 속성(변수), 기능(메서드), 그리고 클래스 간의 관계를 시각적으로 보여주어 전체적인 소스 코드의 구조를 설계할 때 사용합니다. \
지금까지 우리가 이야기했던 추상 클래스, 인터페이스, 결합도 같은 개념들이 이 클래스 다이어그램 안에서 화살표 기호로 시각화됩니다. 
### 🧱 1. 클래스의 3단 구조 표현법
> 다이어그램에서 하나의 클래스는 사각형을 3칸으로 나누어 표현합니다.
- 1층 (이름)
    >클래스명, 추상 클래스명(<<abstract>>), 인터페이스명(<<interface>>)을 적습니다.
- 2층 (속성)
    >멤버 변수의 접근 제어자와 데이터 타입을 적습니다.
- 3층 (기능)
    >메서드의 이름, 매개변수, 반환 타입을 적습니다. 
### 💡 접근 제어자 기호 규칙
- .+ : public (어디서나 접근 가능)
- .- : private (클래스 내부만 접근 가능)
- .# : protected (자식 클래스까지만 접근 가능)
 
### 🎮 2. 유니티 코드가 다이어그램으로 시각화되는 예시
>이전에 다루었던 플레이어, 몬스터, 인터페이스 코드가 클래스 다이어그램으로 변환되면 아래와 같은 구조를 가집니다.
```text
       ┌────────────────────────┐
       │     <<interface>>      │
       │      IDamageable       │
       ├────────────────────────┤
       ├────────────────────────┤
       │ + TakeDamage(amount:int)│
       └───────────▲────────────┘
                   │
                   │ (실선 화살표: 인터페이스 구현)
                   │
       ┌───────────┴────────────┐
       │         Enemy          │
       ├────────────────────────┤
       │ - hp: int              │
       ├────────────────────────┤
       │ + TakeDamage(amount:int)│
       └───────────▲────────────┘
                   │
                   │ (실선 삼각 화살표: 상속)
                   │
       ┌───────────┴────────────┐
       │         Zombie         │
       ├────────────────────────┤
       ├────────────────────────┤
       │ + Attack()             │
       └────────────────────────┘
```
###🔗 3. 클래스 간의 5가지 핵심 관계 기호
>클래스 다이어그램의 핵심은 결합도의 강도에 따라 화살표 모양이 달라진다는 점입니다.
1. 일반화 (Generalization, ───▻)
    - 설명: 상속 관계를 의미합니다. (부모 클래스와 자식 클래스)
    - 표현: 자식에서 부모 클래스 방향으로 속이 빈 삼각형 화살표 실선을 그립니다. 
2. 실현 (Realization, ┈┈┈▻)
    - 설명: 인터페이스 구현 관계를 의미합니다.
    - 표현: 구현 클래스에서 인터페이스 방향으로 속이 빈 삼각형 화살표 점선을 그립니다. 
3.의존 (Dependency, ┈┈┈►)
    - 설명: 한 클래스가 다른 클래스를 단기적으로만 사용하는 관계입니다. (가장 약한 결합)
    - 표현: 사용하는 클래스에서 대상 클래스 방향으로 점선 화살표를 그립니다.
    - C# 코드 형태: 메서드의 매개변수(인자)나 지역 변수로 일시적으로 참조할 때 발생합니다.
```csharp
void Heal(Item potion) { potion.Use(); } // Item에 의존함
```
4. 연관 (Association, ───►)
    - 설명: 한 클래스가 다른 클래스를 지속적으로 알고 지내는 관계입니다.
    - 표현: 실선 화살표로 표현하며, 화살표 옆에 1, 0..* 같은 숫자로 관계의 개수(다중성)를 적기도 합니다.
    - C# 코드 형태: 클래스의 멤버 변수로 가지고 있을 때 발생합니다.
```csharp
public class Player : MonoBehaviour {
    private Weapon currentWeapon; // Weapon과 연관됨 (멤버 변수)
}
```
5. 집약 (Aggregation, ───◆) 및 합성 (Composition, ───◈)
    - 설명: 연관 관계의 특수한 형태로, 전체와 부분의 관계를 나타냅니다.
    - 집약(속이 빈 마름모): 전체 객체가 사라져도 부분 객체는 독립적으로 살아남을 수 있는 관계 (예: 컴퓨터와 마우스).
    - 합성(속이 찬 마름모): 전체 객체가 사라지면 부분 객체도 함께 소멸하는 강한 관계 (예: 유니티에서 프리팹을 지우면 그 안의 자식 오브젝트도 삭제됨). 
### 🚀 클래스 다이어그램을 그리면 얻는 효과
- 코드 작성 전 설계 검증
    >실제 타이핑을 시작하기 전에 데이터 구조와 흐름에 모순이 없는지 미리 Verification(확인)할 수 있습니다.
- 결합도 조절
    >다이어그램을 쭉 펼쳐놓았을 때 특정 클래스에 화살표가 너무 많이 몰려있다면, 그 클래스가 '코드 스멜(거대 클래스)' 상태임을 시각적으로 바로 찾아낼 수 있어 리팩토링의 이정표가 됩니다.
