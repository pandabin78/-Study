# Trashing
> 스래싱(Thrashing)은 가상 메모리 시스템에서 **프로세스의 수행 시간보다 페이지를 교체(디스크 입출력)하는 시간이 더 많아져, CPU성능(이용률)이 급격히 떨어지는 현상**을 말합니다.\
(유저가 입력한'Trashing'의 올바른 컴퓨터 공학 용어 표기 Thrashing입니다.)

### 📉 스래싱이 발생하는 원리
1. 메모리 부족: 다중 프로그래밍 정도(동시에 실행 중인 프로그램 수)가 높아지면 개별 프로세스가 사용할 수 있는 물리 메모리(Ram) 공간이 줄어듭니다.
1. 페이지 부재 빈발: 프로세스가 원활하게 실행되는 데 필요한 최소한의 페이지 프레임 수를 확보하지 못하면, 명령어를 실행할 때마다 **페이지 부재(Page Fault)** 가 연속해서 터집니다.
1. 디스크 I/O 병목 : CPU는 데이터를 읽기 위해 디스크 대기 큐에 멈춰 서게 되고, 시스템은 페이지를 디스크에서 바꾸는 작업(Paging)에만 매달리게 됩니다.

### 📊 스래싱과 CPU 이용률 그래프의 특징
- 다중 프로그래밍 정도(실행 프로그램 수)를 늘리면 처음에는 CPU 이용률이 비례해서 올라갑니다.
- 하지만 특정 임계점을 넘는 순간, 사용 가능한 물리 메모리가 한계에 도달하면서 **CPU 이용률이 바닥으로 수직 낙하** 하게 됩니다. 이 급격한 저하 구간을 '스래싱 발생 지점'이라고 부릅니다.

### 🛠️ 스래싱 해결 및 예방 정책
> 운영체제는 스래싱을 막기 위해 각 프로세스가 필요한 만큼의 충분한 메모리(프레임)를 가변적으로 할당하는 정책을 사용합니다.

- 워킹 세트(Working Set) 알고리즘:
    - 프로세스가 일정 시간(윈도우 크기 Δ)동안 **자주 참조하는 페이지들의 집합(Working Set)을 물리 메모리에 항상 유지해 주는 방식입니다.
    - 워킹 세트 크기의 총합이 현재 가용한 RAM 크기보다 커지면, 운영체제는 일부 프로세스를 통째로 종료(또는 스왑 아웃)시켜 다른 프로세스의 워킹 세트를 보장합니다.
- 페이지 부재 빈도(PFF, Page Fault Frequency) 알고리즘:
    - 프로세스의 **페이지 부재율의 상한선과 하한선**을 설정합니다.
    - 부재율이 상한선을 넘으면 "메모리가 부족하다"고 판단해 프레임을 더 나눠주고, 하한선 밑으로 떨어지면 "메모리가 남는다"고 판단해 프레임을 회수합니다.
- 하드웨어적 해결: 가장 직관적이고 확실한 방법으로, 물리 메모리(RAM) 용량을 중설 합니다
