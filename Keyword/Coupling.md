# 결합도
>결합도(Coupling)는 하나의 소프트웨어 모듈이 다른 모듈에 얼마나 강하게 의존하고 있는지, 즉 모듈 간의 상호 의존성 정도를 뜻합니다.
이전에 다루었던 CBD(컴포넌트 기반 개발)나 추상화의 궁극적인 목표는 이 결합도를 낮추는 것입니다. 좋은 소프트웨어 설계를 위해서는 "낮은 결합도(Loose Coupling)와 높은 응집도(High Cohesion)"를 유지해야 합니다. 결합도가 낮을수록 한 모듈을 수정할 때 다른 모듈이 고장 날 확률이 줄어듭니다.
### 💡 실생활 예시
- 강한 결합 (기차)
    >기차 칸들은 쇠사슬로 단단히 연결되어 있습니다. \
    중간에 있는 칸 하나를 빼거나 바꾸려면 양옆의 칸을 모두 분리하고 멈춰 세워야 하므로 작업이 매우 까다롭습니다.
- 약한 결합 (무선 이어폰)
    >스마트폰과 무선 이어폰은 블루투스(인터페이스)로 연결되어 있습니다. \
    이어폰 브랜드를 바꾸거나 스마트폰을 최신형으로 교체해도 연결 규격만 맞으면 아무런 문제 없이 작동합니다.
### 🎮 유니티(Unity) 코드로 보는 결합도의 차이
>플레이어가 적을 공격하여 데미지를 입히는 상황을 예로 들어보겠습니다.
- ❌ 강한 결합 (Bad: 고치기 힘든 구조)
    >플레이어가 적의 구체적인 클래스(Enemy)를 직접 참조합니다. \
    만약 나중에 부서지는 상자(Box)나 벽(Wall) 같은 오브젝트가 추가되면 플레이어 코드를 전부 뜯어고쳐야 합니다.
```csharp
public class Player : MonoBehaviour
{
    // Enemy 클래스에 직접 의존 (강한 결합)
    public void Attack(Enemy target, int damage)
    {
        target.TakeMonsterDamage(damage); 
    }
}
```

- ⭕ 약한 결합 (Good: 추상화를 통한 결합도 낮추기)
    >인터페이스(IDamageable)라는 중간 완충재를 둡니다. \
    플레이어는 상대방이 적인지, 상자인지 몰라도 되며 오직 "데미지를 입힐 수 있는 규격"만 바라봅니다.
```csharp
public class Player : MonoBehaviour
{
    // 인터페이스에 의존 (약한 결합)
    public void Attack(IDamageable target, int damage)
    {
        target.TakeDamage(damage); // 대상이 무엇이든 한 줄로 해결
    }
}
```
### 📊 결합도의 6가지 단계 (낮을수록 좋음 🟢)
>컴퓨터 공학에서 정의하는 결합도의 단계입니다. \
아래로 내려갈수록 모듈 간의 독립성이 깨지고 유지보수가 지옥이 됩니다.

| 단계 |	결합도 종류	| 설명 | 유니티/C# 관점의 예시 |
| --- | --- | --- | ---|
| 1 🟢 | 자료 결합도(Data | 모듈들이 단순 데이터(파라미터)만 주고받는 가장 이상적인 상태 | Add(int a, int b) 처럼 숫자만 넘겨주는 경우 |
| 2 | 스탬프 결합도(stamp) | 모듈 간에 동일한 데이터 구조(객체, 구조체)를 전달하는 상태 | 메서드 인자로 PlayerData 클래스 자체를 넘길 때 |
| 3 | 제어 결합도(Control) | 한 모듈이 다른 모듈의 내부 흐름을 제어하는 신호를 보내는 상태 | bool isDead 값에 따라 상대방 내부 로직이 완전히 바뀔 때 |
| 4 | 외부 결합도(External) | 외부의 다른 모듈이나 프로토콜, 데이터 포맷에 의존하는 상태 | 외부 API, 플러그인 버전이나 특정 파일 형식에 종속될 때 |
| 5 | 공유 결합도(Common) | 여러 모듈이 하나의 전역 변수(Global Variable)를 공유하는 상태 | 싱글톤(Singleton)이나 전역 데이터 테이블을 마구 참조할 때 |
| 6 🔴 | 내용 결합도(Content) | 한 모듈이 다른 모듈의 내부 변수나 코드를 직접 참조·수정하는 최악의 상태 | 다른 클래스의 private 변수를 강제로 열어 조작하는 경우 |

### 🚀 결합도를 낮추면 얻는 이점
- 독립적인 테스트 가능
    >다른 컴포넌트가 완성되지 않아도 내가 만든 모듈만 떼어내어 유닛 테스트(Unit Test)를 할 수 있습니다.
- 압도적인 재사용성
    >결합도가 낮은 컴포넌트는 현재 프로젝트뿐만 아니라 다음에 만들 다른 프로젝트에도 그대로 복사해서 쓸 수 있습니다.
