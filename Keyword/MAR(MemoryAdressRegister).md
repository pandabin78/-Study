# MAR(Memory Address Register)
>**MAR(메모리 주소 레지스터, Memory Address Register)**은 CPU 내부에서 **"지금 당장 데이터를 읽거나 쓰기 위해 접근하려는 메모리(RAM)의 위치 주소를 기억하는 레지스터"**입니다.\
CPU와 주 기억장치(RAM) 사이에는 데이터를 전달하는 통로가 있습니다. \
MAR은 CPU가 RAM을 향해 "몇 번지 방에 있는 데이터를 내놓아라!" 혹은 **"몇 번지 방에 이 데이터를 저장해라!"**라고 주소를 찍어 보내는 '등기 우편의 주소 라벨' 역할을 합니다.
### 💡 실생활 예시
- 도서관의 사서와 청구기호
    >도서관 사서(CPU)가 서가(RAM)에서 책을 한 권 꺼내오려고 합니다. 사서는 메모지(MAR)에 **'마-105번 서가'**라는 청구기호(주소)를 받아 적습니다. 그리고 그 메모지를 들고 해당 위치로 찾아가 책(데이터)을 꺼냅니다. 이때 청구기호를 임시로 적어둔 메모지가 바로 MAR입니다.
### ⚙️ MAR의 실제 작동 메커니즘 (버스 시스템과의 관계)
> MAR은 CPU 외부에 있는 **주소 버스(Address Bus)**와 직접 연결되어 있습니다. \
CPU가 RAM과 통신할 때 MAR은 다음과 같이 작동합니다.
- 주소 세팅: 제어장치가 다음에 읽을 명령어나 데이터의 주소를 MAR에 전송합니다.
- 주소 버스 방출: MAR에 저장된 주소 값이 주소 버스(단방향 통신)를 타고 RAM의 디코더로 전달됩니다.
- 메모리 위치 지정: RAM은 들어온 주소 값을 확인하고, 해당 주소에 있는 데이터 셀(Cell)을 활성화하여 읽기/쓰기 준비를 마칩니다.
### 🔗 MBR(메모리 버퍼 레지스터)과의 단짝 관계
>MAR을 공부할 때는 항상 세트로 움직이는 **MBR(Memory Buffer Register, 또는 MDR)**을 함께 이해해야 합니다. \
두 레지스터는 CPU와 RAM의 국경선에 서 있는 게이트키퍼들입니다.
- MAR (주소 레지스터): 데이터가 위치한 **"방 번호(주소)"**를 기억합니다. (주소 버스와 연결)
- MBR (버퍼 레지스터): 그 방에서 꺼내온, 혹은 그 방에 집어넣을 **"실제 데이터 내용물"**을 기억합니다. (데이터 버스와 연결)
### 📥 메모리에서 데이터를 읽어올 때 (Read Cycle)
>CPU가 읽고 싶은 주소 200번지를 MAR에 넣습니다.\
200번지 주소가 주소 버스를 통해 RAM으로 갑니다.\
RAM은 200번지에 보관되어 있던 실제 내용물인 값 77을 데이터 버스로 보냅니다.\
이 값 77이 CPU 내부의 MBR에 우선 저장된 후, 최종적으로 연산 장치로 이동합니다.
### 🧱 하드웨어 레지스터 5형제 완벽 지도
>컴퓨터 구조의 기본이 되는 CPU의 5대 핵심 레지스터를 한눈에 스캔할 수 있도록 정리해 드립니다.
```
text
       [ 제어 및 주소 제어 부 ]                       [ 연산 및 데이터 부 ]
 ┌─────────────────────────────────┐           ┌─────────────────────────────┐
 │  PC (다음에 실행할 명령어 주소) │           │  AC (연산 중간 결과 누산기) │
 └────────────────┬────────────────┘           └──────────────┬──────────────┘
                  │                                           │
                  ▼                                           ▼
 ┌─────────────────────────────────┐           ┌─────────────────────────────┐
 │  MAR (지금 접근할 메모리 주소)  │ ◄─────────► │  MBR (지금 이동할 데이터)  │
 └────────────────┬────────────────┘           └──────────────┬──────────────┘
                  │ (주소 버스)                               │ (데이터 버스)
 ─────────────────┼───────────────────────────────────────────┼───────────────
                  ▼                                           ▼
         [ 주소 디코더 ]                                [ 데이터 셀 ]
         ┌───────────────────────────────────────────────────────────┐
         │                    메인 메모리 (RAM)                      │
         └───────────────────────────────────────────────────────────┘
```
### 🚀 개발자 관점에서의 팁: 64비트 운영체제의 비밀
>우리가 윈도우나 Mac 환경에서 프로그램을 빌드할 때 **x64(64비트)**로 타겟을 잡습니다. 이 '64비트 컴퓨터'라는 말의 하드웨어적 본질이 바로 이 MAR의 크기와 연결됩니다.\
64비트 CPU란 내부 레지스터, 특히 **MAR의 크기가 64비트(64비트 주소 버스)**라는 뜻입니다.\
MAR이 64비트이면 \
개의 서로 다른 메모리 주소를 표현할 수 있으므로 이론상 최대 16EB(엑사바이트)라는 상상할 수 없을 만큼 거대한 RAM 용량을 인식하고 컨트롤할 수 있게 됩니다. \
(과거 32비트 CPU의 MAR은 최대 4GB의 RAM만 인식할 수 있었던 한계가 여기서 나옵니다.)
