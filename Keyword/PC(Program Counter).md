# PC(Program Counter)
>**PC(프로그램 카운터, Program Counter)**는 컴퓨터의 중앙처리장치(CPU) 내부에 있는 핵심 레지스터(Register) 중 하나로, **"다음에 실행할 명령어(Instruction)의 메모리 주소를 보관하는 기억 장치"**입니다. \
컴퓨터가 멈추지 않고 순차적으로 프로그램을 실행할 수 있도록 교통정리를 해주는 '나침반' 역할을 합니다. \
Intel 계열(x86/x64) 아키텍처에서는 **IP(명령 포인터, Instruction Pointer)**라고도 부릅니다.
### 💡 실생활 예시
>악보를 읽는 연주자: 음악가가 노래를 연주할 때 현재 마디를 연주하면서도, 눈은 이미 **'다음에 연주해야 할 마디(PC)'**를 바라보고 있습니다. \
한 마디 연주가 끝나면 시선은 자동으로 다음 마디로 넘어가며, 도돌이표(반복문/조건문)를 만나면 지정된 다른 마디로 시선이 점프합니다.
### ⚙️ CPU 명령어 사이클에서 PC의 작동 과정
>CPU가 프로그램을 실행하는 제어 사이클(Instruction Cycle)에서 PC는 다음과 같이 정밀하게 움직입니다.
- 인출 (Fetch - 가져오기)
    >CPU는 현재 PC가 가리키고 있는 메모리 주소를 보고, 그 주소에 저장된 명령어를 메모리(RAM)에서 꺼내와 명령 레지스터(IR)에 담습니다.
- PC 값 자동 증가 (Increment)
    >명령어를 인출하자마자, PC는 자동으로 다음 명령어의 주소값만큼 증가하여 다음 명령을 가리킬 준비를 마칩니다. \
    (예: 64비트 CPU에서 명령어 크기가 8바이트라면 PC = PC + 8)
- 해독 및 실행 (Decode & Execute)
    >가져온 명령어를 분석하고 실행합니다.
### 🔄 조건문과 반복문을 만났을 때의 PC (점프)
>일반적인 상황에서 PC는 위에서 아래로 주소가 1, 2, 3, 4... 순차적으로 증가합니다. \
하지만 코드에서 if, for, while 같은 제어문이나 함수 호출을 만나면 순서가 바뀝니다.
- 분기 명령(Branch/Jump)
    >프로그램 실행 중 조건문이나 루프를 만나면, PC는 순차적인 다음 주소가 아니라 조건에 부합하는 완전히 엉뚱한 메모리 주소(예: 주소 100번지)로 값을 강제로 덮어씁니다. \
    이로 인해 CPU는 다음 사이클에서 그 점프한 주소의 명령을 읽어 들이게 됩니다.
- 함수 호출(Call/Return)
    >새로운 함수로 점프하기 전, 돌아올 원래 주소를 스택(Stack) 메모리에 안전하게 저장(Push)해 둔 뒤 PC 값을 함수의 시작 주소로 바꿉니다. \
    함수의 실행이 끝나면(return) 스택에 보관했던 주소를 다시 PC에 복원(Pop)하여 원래 흐름으로 돌아옵니다. 
### 🎮 소프트웨어 및 유니티 개발자와의 연결고리
>하드웨어 레지스터인 PC는 소프트웨어 엔진 및 개발 환경에서도 중요한 개념으로 치환됩니다.
- 디버깅의 '노란색 화살표'
    >Visual Studio나 Rider에서 코드에 중단점(Breakpoint)을 잡고 디버깅할 때, 현재 멈춰 서 있는 줄을 가리키는 노란색 화살표가 바로 논리적인 프로그램 카운터(PC)의 현재 위치를 시각적으로 보여주는 것입니다.
- 유니티 코루틴(Coroutine)
    >유니티에서 yield return을 사용하는 코루틴은 실행 도중 특정 지점에서 멈췄다가 다음 프레임에 다시 이어집니다. \
    내부적으로 유니티 엔진은 코루틴 함수의 **실행 상태(상태 머신과 일종의 PC 역할)**를 기억해 두었다가, 멈췄던 바로 다음 라인부터 코드를 실행할 수 있도록 제어합니다.
