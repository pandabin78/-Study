# 캐시 메모리
>캐시 메모리(Cache Memory)는 CPU와 주기억장치(RAM) 사이의 속도 차이를 극복하기 위해 사용되는 고속 반도체 기억장치입니다.CPU가 데이터를 요청할 때 주 메모리까지 가지 않고 빠르게 데이터를 읽고 쓸 수 있도록 자주 사용하는 데이터를 임시 저장합니다.
구조, 원리, 그리고 종류별 핵심 정보는 다음과 같습니다.

### 📌 캐시 메모리의 핵심 원리: 지역성 (Locality)
>캐시 메모리가 효율적으로 작동하는 이유는 프로그램이 특정 데이터나 위치를 집중적으로 참조하는 적중률(Hit Ratio) 기반의 '지역성의 원리'를 따르기 때문입니다.

- 시간 지역성 (Temporal Locality): 
    >최근에 참조된 주소의 데이터는 곧 다시 참조될 가능성이 높음 (예: 반복문 코드, 변수).
- 공간 지역성 (Spatial Locality): 
    >참조된 주소와 인접한 주소의 데이터가 곧 참조될 가능성이 높음 (예: 배열, 순차적 코드 실행).

### ⚙️ 캐시의 구조와 계층 (L1, L2, L3)
>CPU 내부와 주변에는 속도와 용량에 따라 계층 구조로 배치됩니다. 

- L1 캐시 (Level 1): 
    >CPU 코어 내부에 위치하며 속도가 가장 빠르지만 용량이 매우 작음 (보통 수십 KB). 명령어 캐시(I-Cache)와 데이터 캐시(D-Cache)로 분리되어 있는 경우가 많음.
- L2 캐시 (Level 2): 
    >코어마다 또는 공유 형태로 존재하며, L1보다 느리지만 용량이 더 큼 (보통 수백 KB ~ 수 MB).
- L3 캐시 (Level 3): 
    >여러 코어가 공유하는 대용량 캐시로, 멀티코어 CPU의 성능 향상에 기여함 (보통 수십 MB).

### 🔄 캐시 쓰기 정책 (Write Policy)
>CPU가 캐시에 데이터를 저장할 때, 주 메모리(RAM)의 내용도 함께 업데이트해야 합니다. 이때 사용하는 방식입니다.

- Write-Through (직접 쓰기): 
    >캐시와 메모리에 동시에 데이터를 기록하는 방식입니다. 구조가 단순하고 데이터 일관성이 보장되지만 메모리 쓰기 속도 때문에 지연이 발생합니다.
- Write-Back (나중 쓰기): 
    >캐시에만 먼저 기록한 뒤, 해당 캐시 블록이 다른 데이터로 교체될 때만 메모리에 기록하는 방식입니다. 속도가 빠르지만 제어가 복잡하고 전원 차단 시 데이터 손실 위험이 있습니다.

### 🔍 매핑 프로세스 (Mapping Process)
>주메모리의 데이터를 캐시 메모리로 가져올 때 위치를 지정하는 방법입니다.

- 직접 매핑 (Direct Mapping): 
    >주메모리의 블록들이 캐시의 정해진 위치에만 들어갈 수 있는 방식 (단순하지만 충돌 가능성 높음).
- 연관 매핑 (Fully Associative Mapping): 
    >비어 있는 캐시 슬롯 어디든 들어갈 수 있는 방식 (적중률이 높지만 탐색 회로가 복잡하고 비용이 비쌈).
- 세트 연관 매핑 (Set Associative Mapping): 
    >위 두 방식을 절충하여 캐시를 여러 세트로 나누고, 각 세트 내에서 자유롭게 배치하는 방식 (현재 가장 많이 쓰임)
