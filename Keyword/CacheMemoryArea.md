# 캐시 메모리 지역성
>캐시 메모리 지역성(Locality of Reference)은 CPU가 메모리(RAM)의 데이터에 접근할 때, 최근에 접근했던 데이터나 그 주변의 데이터에 다시 접근할 가능성이 극도로 높다는 특성을 뜻합니다.

>이전에 다루었던 MAR과 MBR을 통해 CPU가 매번 느린 RAM과 직접 소통하면 병목 현상이 생깁니다. \
이를 막기 위해 CPU와 RAM 사이에 초고속 반도체인 캐시 메모리(Cache Memory)를 두고, 이 지역성 원리를 이용해 조만간 쓰일 것 같은 데이터를 미리 한 보따리 가져다 놓음으로써 시스템 속도를 비약적으로 향상시킵니다.

### 💡 실생활 예시
- 책상 위의 책(캐시)과 서재(RAM): 
    >여러분이 리포트를 작성할 때, 필요한 책(데이터)을 찾으려고 매번 거실에 있는 서재(RAM)까지 걸어갔다 오는 것은 매우 비효율적입니다. 보통 자주 보는 책 몇 권은 방 책상 위(캐시 메모리)에 꺼내놓고 봅니다.
- >또한, 참고 문헌 13페이지를 읽었다면 다음 순간에는 14페이지(주변 데이터)를 읽을 확률이 높고, 방금 읽은 문장을 다시 정독(최근 데이터)할 확률이 높습니다. 이 성질이 바로 지역성입니다.

### 🛠️ 캐시 메모리 지역성의 3가지 종류
>캐시 메모리가 데이터를 예측하여 채워 넣는 기준은 크게 세 가지로 나뉩니다.

1. 시간 지역성 (Temporal Locality)
- 정의: 
    >최근에 한 번 접근했던 메모리 공간은 곧(가까운 미래에) 다시 접근할 가능성이 높다는 특성입니다.
- C# / 유니티 코드 예시: 
    >반복문 내에서 계속 누적되는 루프 제어 변수나 데이터입니다.

```cs
totalGold = 0;
for (int i = 0; i < 1000; i++)
{
    totalGold += monsterGolds[i]; // totalGold와 i 변수는 매 루프마다 반복해서 접근하므로 시간 지역성이 극도로 높음!
}
```

#### 2. 공간 지역성 (Spatial Locality)
- 정의: 
    >한 번 접근한 메모리 주소와 그 주변(인접한) 주소의 데이터 역시 곧 접근할 가능성이 높다는 특성입니다. CPU가 메모리에서 데이터를 가져올 때 단 1바이트만 딱 가져오지 않고, 주변 데이터까지 한 묶음(Cache Line)으로 긁어오는 이유입니다.
- C# / 유니티 코드 예시: 
    >메모리에 데이터가 일렬로 나란히 연속되어 배치되는 배열(Array) 자료구조입니다.

```cs
// 배열은 메모리 공간에 빈틈없이 연속으로 저장됩니다.
int[] playerScores = new int[5] { 10, 20, 30, 40, 50 };

// scores[0]에 접근한 직후, 바로 옆 칸인 scores[1], scores[2]에 순차 접근하므로 공간 지역성이 폭발합니다.
for (int i = 0; i < playerScores.Length; i++) {
    Debug.Log(playerScores[i]); 
}
```

#### 3. 순차 지역성 (Sequential Locality)
- 정의: 
    >데이터가 기억장치에 저장된 순서대로 순차적으로 실행되는 특성입니다. 프로그램의 코드가 명령어 주소 순서대로 위에서 아래로 실행되는 특성 자체가 이에 해당합니다. (이전에 다룬 PC(프로그램 카운터)가 자동으로 +1, +4씩 증가하며 명령을 읽는 원동력입니다.)

### 🎮 유니티 개발자 관점에서의 중요성: DOTS와 캐시 히트
>유니티 실무나 게임 엔진 최적화에서 캐시 지역성은 성능을 판가름하는 가장 핵심적인 키워드입니다.

- 캐시 히트(Cache Hit)와 캐시 미스(Cache Miss): 
    >CPU가 필요한 데이터를 캐시 메모리에서 바로 찾으면 캐시 히트라고 하며 초고속으로 처리됩니다. 반면 캐시에 없어서 느린 RAM까지 MAR 주소를 던져 가져와야 하면 캐시 미스가 발생해 심각한 병목(렉)이 생깁니다.
- C# List와 구조체 배열의 차이: 
    >C#에서 List<MyClass>를 만들어 관리하면 데이터들이 메모리 사방에 파편화되어 저장되므로(추상화와 유연성은 높지만) 공간 지역성이 깨져 캐시 미스가 자주 납니다. 반면 구조체 배열(MyStruct[])이나 일반 배열은 메모리에 직렬로 배치되어 캐시 히트율이 극대화됩니다.
- 유니티 DOTS (Data-Oriented Technology Stack):
    >유니티의 차세대 기술인 DOTS와 ECS 아키텍처의 핵심 철학이 바로 이것입니다. 기존의 객체 지향(OOP) 스타일인 거대 클래스(컴포넌트) 구조를 과감히 버리고, 데이터를 메모리에 일렬로 이쁘게 모아놓아 CPU의 캐시 메모리 지역성을 극한까지 끌어올려 수만 개의 오브젝트를 랙 없이 돌리는 기술입니다.
