# 캐시 메모리 매핑
>캐시 메모리 매핑(Cache Memory Mapping)은 주 기억장치(RAM)의 거대한 데이터를 크기가 훨씬 작은 초고속 캐시 메모리에 어떤 규칙으로 배치할지 결정하는 주소 변환 방법입니다.

>이전에 다루었던 캐시 메모리 지역성을 활용해 RAM의 데이터를 캐시로 가져오려면, 캐시의 어느 빈 칸(라인)에 넣어야 나중에 CPU가 MAR로 주소를 조회했을 때 헷갈리지 않고 초고속으로 찾을 수 있을지 규칙이 필요합니다. 이 규칙에 따라 3가지 매핑 방식이 존재합니다.

### ?? 실생활 예시 (대학교 기숙사 방 배정)
>RAM(10,000명의 학생) ?? 캐시 메모리(100개의 기숙사 방)로 방을 배정하는 상황입니다.

- 직접 매핑: 
    >"학번 끝자리 두 자리가 방 번호다." (99번 학생은 무조건 99호실로) ?? 찾기 쉽지만 방 주인이 겹치면 싸움이 납니다.
- 연관 매핑: 
    >"비어 있는 방 아무 데나 들어가라." ?? 방이 꽉 찰 때까지 싸울 일은 없지만, 학생을 찾으려면 100개 방을 다 두드려야 합니다.
- 세트 연관 매핑
    >"학번 끝자리에 따라 지정된 구역(A동, B동) 내의 빈 방으로 들어가라." ?? 양쪽의 장점을 합친 현대의 방식입니다.

### ??? 캐시 메모리 매핑의 3가지 핵심 방식
>CPU가 RAM 주소를 조회할 때, 주소 비트를 태그(Tag), 인덱스(Index) 등의 필드로 쪼개어 캐시 메모리 위치를 식별합니다.

1. 직접 매핑 (Direct Mapping)
    - 개념: RAM의 특정 주소는 캐시 메모리의 딱 지정된 하나의 라인에만 들어갈 수 있는 1:1 고정 규칙 방식입니다. (RAM 주소를 캐시 크기로 나눈 나머지(Modulo) 값을 인덱스로 사용)
    - 장점: 매핑 구조가 단순하고, CPU가 캐시를 뒤질 때 지정된 칸만 보면 되므로 검색 속도가 폭발적으로 빠릅니다.
    - 단점: 캐시 메모리가 텅텅 비어 있어도, 하필 번호가 겹치는 데이터(예: 기숙사 99호실을 써야 하는 학생 2명)가 번갈아 호출되면 기존 캐시를 계속 지우고 새로 쓰느라 캐시 미스가 무한 반복되는 병목(Thrashing, 스래싱)이 발생합니다.

2. 연관 매핑 (Associative Mapping)
    - 개념: 고정된 위치 규칙 없이, RAM의 데이터를 캐시 메모리의 비어 있는 어떤 라인이든 자유롭게 들어갈 수 있는 방식입니다.
    - 장점: 주소가 겹쳐서 발생하는 충돌이 전혀 없기 때문에 공간을 알뜰하게 쓰며, 캐시 히트율(Hit Ratio)이 3가지 방식 중 가장 높습니다.
    - 단점: 특정 데이터를 찾으려고 할 때 캐시의 모든 라인을 처음부터 끝까지 다 뒤져봐야(Parallel Search) 하므로, 내부 회로가 복잡해지고 하드웨어 비용이 비싸지며 탐색 시간이 길어질 수 있습니다.

3. 세트 연관 매핑 (Set Associative Mapping)
    - 개념: 직접 매핑과 연관 매핑의 장점만 섞은 현대 컴퓨터 CPU(Intel, AMD 등)의 표준 방식입니다. 캐시 라인들을 여러 개의 '세트(Set)'로 묶은 뒤, 세트 번호는 직접 매핑(지정)하고, 그 세트 내부에서는 연관 매핑(자유 배치)을 합니다.
    - 특징: 보통 한 세트에 2개 또는 4개의 라인을 두는 2-Way 또는 4-Way Set Associative 방식을 주로 씁니다.
    - 효과: 직접 매핑의 충돌 위험을 크게 줄이면서도, 연관 매핑처럼 전체를 다 뒤질 필요 없이 지정된 세트 내부만 검색하면 되므로 속도와 효율의 밸런스가 완벽합니다.

### ?? 캐시 매핑 방식 한눈에 비교 요약

| 방식 | 위치 지정 규칙 | 검색 속도 | 캐시 히트율 | 하드웨어 복잡도/비용 |
|---|---|---|---|---|
| 직접 매핑 | 엄격함 (저정된 1칸만) | 매우빠름 | 낮음 (충돌 잦음) | 단순함 / 저렴함 |
| 연관 매핑 | 없음 (비어있는 아무 칸) | 느림 (전수 조사) | 매우 높음 | 매우 복잡 / 비쌈 |
| 세트 연관 | 중간 (지정된 구역 내 자유) | 빠름 | 높음 | 적당함 (현대 표준) |

### ?? 개발자 관점에서의 팁
>소프트웨어 개발자가 이 하드웨어 매핑 구조를 이해하면 캐시 친화적 코드(Cache-Friendly Code)의 깊이가 달라집니다.

- 세트 연관 매핑과 2차원 배열: 
    >C#이나 C++에서 대형 2차원 배열을 다룰 때, 공간 지역성을 깨뜨리는 방식으로 루프를 돌리면(예: 행 중심이 아닌 열 중심으로 탐색), 캐시 매핑 규칙 상 동일한 세트에 계속해서 캐시 미스가 발생하며 성능이 수십 배까지 떨어질 수 있습니다.
- 하드웨어(CPU)는 개발자가 짠 메모리 배치 순서를 기반으로 이 매핑 규칙을 적용하기 때문에, 데이터를 연속적으로 이쁘게 배치하는 능력이 성능 최적화의 기본입니다.
