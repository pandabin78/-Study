# 캐시 메모리 일관성
>캐시 메모리 일관성(Cache Coherence)이란 멀티코어 프로세서 시스템에서 여러 개의 코어가 각각 자신만의 로컬 캐시 메모리를 가지고 있을 때, 모든 코어가 동일한 메모리 주소에 대해 항상 최신의 일치된 데이터를 바라보도록 보장하는 성질을 뜻합니다.

>이전에 다루었던 캐시 메모리 지역성에 의해 CPU 코어들은 데이터를 캐시에 복사해 두고 사용합니다. 하지만 멀티코어 환경에서 여러 코어가 하나의 메인 메모리(RAM)를 공유하게 되면서, 서로 같은 데이터를 수정할 때 데이터 불일치 문제가 발생합니다. 이 문제를 해결하기 위해 시스템 하드웨어 레벨에서 일관성을 강제하게 됩니다.

### ⚠️ 일관성이 깨지는 원인 (데이터 불일치 상황)
>예를 들어 메인 메모리에 변수 X = 10이 저장되어 있고, 코어 A와 코어 B가 이 값을 동시에 읽어 각자의 캐시에 보관하고 있다고 가정해 보겠습니다.

1. 상황: 코어 A가 게임 캐릭터의 골드를 수정하여 자신의 캐시 값을 X = 20으로 업데이트합니다.
1. 문제: 이때 메인 메모리와 코어 B의 캐시에 있는 X는 여전히 10인 상태입니다.
1. 결과: 이 상태에서 코어 B가 값을 읽으면 수정 전의 과거 데이터(10)를 읽게 되며, 연산 처리에 치명적인 데이터 오염(버그)이 발생합니다.

### 🛠️ 캐시 일관성을 유지하기 위한 2가지 하드웨어 접근법
>하드웨어 아키텍처는 주로 다음 두 가지 방식을 사용하여 각 코어의 캐시 상태를 감시하고 동기화합니다.

1. 스누핑 프로토콜 (Snooping Protocol)
    - 개념: 각 코어의 캐시 제어기가 시스템 공유 버스(Bus)를 통해 오고 가는 메모리 트랜잭션 주소 신호를 계속 '스누핑(Snoop: 기웃거리며 감시)'하는 방식입니다.
    - 동작: 어떤 코어가 특정 메모리 주소의 데이터를 수정하는 신호를 포착하면, 동일한 주소 데이터를 가진 다른 코어들은 자신의 캐시 데이터를 즉시 무효화(Invalidate)하거나 업데이트(Update)합니다.
    - 특징: 코어 수가 적은 일반 소형/개인용 컴퓨터 아키텍처에서 매우 효율적입니다.

2. 디렉토리 기반 프로토콜 (Directory-based Protocol)
    - 개념: 중앙에 특정 데이터가 어느 코어의 캐시에 복사되어 들어가 있는지를 기록하는 중앙 디렉토리(메모리 테이블)를 둡니다.
    - 동작: 공유 데이터를 수정하려는 코어는 먼저 중앙 디렉토리에 허가를 요청하고, 디렉토리가 해당 데이터를 가진 코어들에게만 콕 집어서 무효화 명령을 전달합니다.
    - 특징: 모든 캐시가 버스를 가득 채우며 방송(Broadcasting)할 필요가 없으므로, 코어가 수십~수백 개에 달하는 대규모 대형 서버 및 고성능 컴퓨팅(HPC) 시스템에 적합합니다.

### 📊 가장 대표적인 상태 관리 규칙: MESI 프로토콜
>스누핑 방식에서 캐시 라인의 상태를 4가지 플래그(Flag)로 나누어 일관성을 통제하는 MESI 프로토콜이 가장 표준적으로 쓰입니다.

| 상태 기호 | 상태 이름(State) | 설명 (내 캐시에 들어있는 데이터의 상태)
| --- | --- | --- |
| M | Modified(수정) | 이 데이터는 오직 내 캐시에만 유일하게 존재하며, 원본 메인 메모리 값과 다르게 내가 수정한 상태입니다.(추후 메모리에 다시 적어주어야 함) |
| E | Exclusive(전용) | 메인 메모리의 내용과 완벽히 일치하지만, 현재 이 시스템에서 나 혼자만 복사해서 가지고 있는 상태입니다. |
| S | Shared(공유) | 메인 메모리와 일치하며, 나 말고도 다른 코어의 캐시에도 동일한 복사본이 함께 올라와 있는 상태입니다.(읽기만 가능) |
| I | Invalid(무효) | 다른 코어가 데이터를 수정했기 때문에, 내 캐시에 들어있는 이 데이터 오염된 쓰레기 값(사용 불가능) 인 상태입니다. |

- 작동 원리: 내가 Shared(S) 상태인 데이터를 수정하려고 하면, 버스 신호를 보내 다른 코어들의 상태를 전부 Invalid(I)로 폭파시킨 후, 내 상태를 Modified(M)로 바꿉니다.

### 🎮 소프트웨어 및 멀티스레드 개발자와의 연결고리
>하드웨어가 캐시 일관성을 알아서 보장해 주더라도, CPU 레지스터 연산 속도와 컴파일러의 최적화(코드 순서 뒤바꿈) 과정 때문에 소프트웨어 레벨에서 동기화 문제가 여전히 터집니다

- C# volatile 키워드: 멀티스레드 프로그래밍을 할 때 변수 앞에 volatile을 붙이면, 컴파일러가 해당 변수를 캐시에만 머물게 하지 않고 매번 메인 메모리에서 직접 쓰고 읽도록 강제하여 코어 간 데이터 불일치를 프로그래밍 적으로 방어합니다.
- 유니티 잡 시스템(Job System)과 데이터 경합: 유니티에서 여러 스레드가 동시에 안전하게 연산하도록 돕는 Job System은 한 스레드가 데이터를 수정하는 도중 다른 스레드가 그 데이터에 접근하는 행동을 하드웨어 레벨의 성능 손실 없이 격리하도록 유도합니다. (데이터 경합 방지)
