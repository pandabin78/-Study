# 가상메모리 페이징
>가상메모리 페이징(Paging)은 가상 주소 공간과 물리 메모리를 고정된 크기의 작은 블록으로 나누어 관리하는 메모리 관리 기법입니다. \
현대 운영체제(Windows, Linux, macOS 등)가 가상 메모리를 구현할 때 가장 기본적으로 사용하는 방식입니다.

### ?? 페이징의 핵심 개념: 고정 크기 분할
>페이징 기법은 메모리를 논리적 내용과 상관없이 동일한 크기로 쪼갭니다 

- 페이지 (Page): 가상 메모리를 나눈 고정 크기의 블록 (프로세스 관점)
- 프레임 (Frame): 물리 메모리(RAM)를 나눈 고정 크기의 블록 (실제 하드웨어 관점)
- 크기 일치: 페이지의 크기와 프레임의 크기는 정확히 일치합니다 (보통 4KB 사용)

### ?? 주소 변환 매커니즘 (Address Translation)
>CPU가 생성하는 가상 주소는 매핑 테이블인 페이지 테이블(Page Table)을 거쳐 실제 물리 주소로 변환됩니다

1. 페이지 번호 (p): 해당 데이터가 몇 번째 페이지에 있는지 나타냅니다
1. 변위/오프셋 (d): 해당 페이지의 시작 지점부터 얼마나 떨어져 있는지 나타냅니다 

#### [변환 과정]

1. CPU가 가상 주소 (p, d)를 요청합니다
1. MMU(메모리 관리 장치)가 페이지 테이블에서 p번째 항목(PTE)을 찾습니다
1. 테이블에서 매핑된 물리 메모리의 프레임 번호 (f)를 알아냅니다
1. 프레임 번호 f와 기존 오프셋 d를 결합하여 최종 물리 주소 (f, d)를 완성하고 RAM에 접근합니다 

### ? 속도 향상을 위한 하드웨어: TLB (Translation Lookaside Buffer)
>페이지 테이블은 대개 용량이 커서 RAM에 저장됩니다. \
이 때문에 CPU가 메모리에서 데이터를 한 번 읽으려면 [페이지 테이블 접근] + [실제 데이터 접근] 총 2번의 RAM 접근이 필요해 속도가 느려집니다.

- TLB Hit: 최근에 변환했던 페이지 번호가 TLB에 있다면, RAM의 페이지 테이블을 거치지 않고 즉시 물리 주소로 변환합니다.
- TLB Miss: TLB에 없다면 기존 방식대로 RAM의 페이지 테이블을 조회한 후, 해당 정보를 TLB에 업데이트합니다.

### ?? 페이징의 장점과 단점
- 장점 (외부 단편화 해결): 물리 메모리의 빈 프레임이 있으면 순서와 상관없이 페이지를 아무 데나 끼워 넣을 수 있어 메인 메모리 낭비 공간이 사라집니다
- 단점 (내부 단편화 발생): 프로세스의 마지막 페이지가 딱 4KB 크기로 떨어지지 않으면 남는 공간이 생깁니다 (예: 13KB 프로세스는 4KB 페이지 4개(16KB)가 필요하므로 마지막 페이지에 3KB의 낭비 공간 발생)
