# AC(Accumulator)
>AC(누산기, Accumulator)는 CPU 내부의 핵심 연산 장치인 ALU(산술논리연산장치) 바로 옆에 위치한 가장 중요한 데이터 레지스터로, "산술 및 논리 연산의 중간 결과나 최종 계산 값을 일시적으로 기억하는 장치"입니다.\
컴퓨터가 연산을 수행할 때마다 매번 속도가 느린 메인 메모리(RAM)에 접근해서 데이터를 쓰고 읽으면 엄청난 병목 현상이 발생합니다. \
AC는 이러한 문제를 해결하기 위해 CPU 내부에서 초고속으로 계산 결과를 보관하는 '임시 메모장' 역할을 합니다.
### 💡 실생활 예시
>전자계산기를 두드리는 사람: 여러분이 계산기로 5 + 3 + 2를 계산할 때, 5 + 3을 누르면 화면에 중간 결과인 8이 잠시 뜹니다.\
그리고 메모장에 적어둘 필요 없이 그 상태에서 바로 + 2를 눌러 최종 결과인 10을 얻습니다. 이때 중간 결과와 최종 결과를 계속해서 띄워주고 있는 계산기 화면이 바로 AC(누산기)입니다.
### ⚙️ 연산 과정으로 보는 레지스터들의 협업 (AC의 작동)
>CPU가 A 변수의 값(5)과 B 변수의 값(3)을 더해 다시 A에 저장하는 코드(A = A + B)를 실행할 때, AC는 다음과 같이 중심에서 작동합니다.
- 초기화: 메모리에서 A(5)의 값을 읽어와 AC에 먼저 저장해 둡니다. (현재 AC = 5)
- 데이터 로드: 더할 대상인 B(3)의 값을 메모리에서 읽어와 또 다른 레지스터인 데이터 레지스터(DR 또는 MBR)에 임시로 둡니다.
- 연산 수행: ALU가 AC의 값(5)과 DR의 값(3)을 가져와 더하기 연산을 수행합니다.
- 결과 누적(Accumulate): 계산 결과로 나온 값 8은 메모리로 바로 가지 않고, 다시 AC에 덮어써집니다. (현재 AC = 8)
- 최종 저장: 더 이상 할 연산이 없다면 AC에 남아있는 최종 결과 8을 원래 메모리의 A 주소로 보냅니다.
### 🧱 하드웨어 레지스터 3형제 최종 비교 요약
>지금까지 살펴보신 CPU의 핵심 레지스터 3가지를 명확하게 정리해 드리겠습니다. 이 세 장치가 톱니바퀴처럼 맞물려 컴퓨터가 작동합니다.

| 레지스터 이름 | 가리키는/담고 있는 것 | 비유 | 주요 역할 |
| --- | --- | --- | --- |
| PC(Program Counter) |	다음에 실행할 명령어의 메모리 주소 | 나침반 / 페이지 번호 |	다음 실행 흐름 제어 |
| IR(Instruction Register) | 지금 막 가져와서 실행 중인 명령어 본체 | 현재 읽고 있는 레시피 문장 | 명령어 해독 및 제어 신호 생성 |
| AC(Accumulator) | 연산장치(ALU)가 계산한 데이터 결과 값 | 계산기 화면 / 임시 메모장 | 연산 속도 극대화 및 중간 값 보관 |

### 🚀 개발자 관점에서의 이해
>고급 언어(C#, C++)에서 total += score; 같은 누적 연산 코드를 작성하면, 어셈블리어 레벨에서는 100% CPU의 AC(누산기) 레지스터를 사용하는 명령어로 변환됩니다.\
유니티에서 캐릭터가 몬스터를 연속으로 공격해 콤보 수(comboCount++)를 올리거나, 골드를 획득해 자산(gold += 100)을 축적할 때도 CPU 내부에서는 매 클럭마다 이 AC 레지스터가 쉴 새 없이 값을 지우고 새로 쓰며 작동하고 있습니다.
