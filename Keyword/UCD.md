# 유즈케이스 다이어그램
>유즈케이스 다이어그램(Use Case Diagram)은 시스템이 제공해야 하는 기능과 이를 사용하는 사용자(인간 또는 외부 시스템) 간의 상호작용을 사용자 관점에서 시각적으로 표현한 다이어그램입니다. \
UML(통합 모델링 언어)의 하나로, 개발자가 아닌 기획자나 고객도 시스템의 전체적인 범위를 한눈에 쉽게 이해할 수 있도록 돕는 역할을 합니다. \
소프트웨어 생명 주기(SDLC) 중 요구사항 분석 단계에서 주로 작성됩니다. 
### 🧱 유즈케이스 다이어그램의 4대 핵심 구성 요소
>다이어그램을 그릴 때 사용하는 도형과 기호는 다음과 같이 규격화되어 있습니다.
- 액터 (Actor, 👤)
    >시스템과 상호작용하는 외부 엔티티입니다. 주로 사람(플레이어, 관리자)이지만, 외부 시스템(결제 모듈, 서버)이 될 수도 있습니다.
- 유즈케이스 (Use Case)
    >시스템이 제공하는 독립적인 기능 단위입니다. 타원형 모양 안에 '로그인하기', '공격하기' 처럼 동사형태 명칭으로 작성합니다.
- 시스템 경계 (System Boundary, 🔲)
    >사각형 박스로 표현하며, 우리가 개발할 시스템의 범위를 명확히 구별해 줍니다. 액터는 박스 밖에, 유즈케이스는 박스 안에 위치합니다.
- 관계 (Relationship, ➡️)
    >액터와 유즈케이스, 또는 유즈케이스 간의 상호작용을 선으로 연결합니다. 
#### 🎮 유니티(Unity) 게임 시스템으로 보는 예시
>온라인 게임 시스템을 기획할 때 작성할 수 있는 유즈케이스 다이어그램의 구성을 텍스트로 시각화한 모습입니다.
```
text
  👤 [플레이어] ──────────────────┐
     (액터)                      │
                                 ▼
                    ┌───────────────────────────┐
                    │  🎮 게임 시스템 (경계)     │
                    │                           │
                    │   ( 로그인하기 ) ◄───┐    │
                    │                      │    │
                    │   ( 캐릭터 이동 )    │    │
                    │                      │    │ (include)
                    │   ( 몬스터 공격 ) ───┼────┘
                    │          │          │     │
                    │          │          └───( 상점 이용 )
                    │          ▼ (exclude)      ▲
                    │   [ 치명타 발상 ]         │
                    └───────────────────────────┘
                                                │
  🖥️ [결제 시스템] ─────────────────────────────┘
    (외부 액터)
```
### 🔗 유즈케이스 간의 3가지 핵심 관계
>다이어그램에서 유즈케이스끼리 연결할 때 사용하는 화살표 규격입니다. 면접이나 자격증 시험에서도 단골로 출제되는 중요한 개념입니다. 
1. 연관 관계 (Association)
    - 설명
        >액터와 유즈케이스 간의 단순한 상호작용을 나타냅니다.
    - 표현
        >실선으로 연결합니다.
    - 예시
        >플레이어 ─── 몬스터 공격 
2. 포함 관계 (Include)
    - 설명
        >하나의 유즈케이스를 수행할 때, 반드시 먼저 혹은 함께 실행되어야 하는 다른 유즈케이스와의 관계입니다.
    - 표현
        ><<include>>라는 글자가 적힌 점선 화살표로 조건이 되는 유즈케이스를 가리킵니다.
    - 예시
        >몬스터 공격 ───<<include>>───► 로그인하기 (공격을 하려면 무조건 로그인이 되어 있어야 함)
3. 확장 관계 (Exclude / Extend) 
    - 설명
        >특정 조건이 만족할 때만 선택적으로 실행되는 유즈케이스와의 관계입니다.
    - 표현
        ><<extend>>라는 글자가 적힌 점선 화살표로 원본 유즈케이스를 가리킵니다.
    - 예시
        >치명타 발생 ───<<extend>>───► 몬스터 공격 (공격을 할 때 확률적으로만 치명타가 발동함) 
### 🚀 유즈케이스 다이어그램의 효과
- 요구사항 명확화
    >개발에 들어가기 전, 고객이 원하는 기능이 누락되었거나 잘못 이해한 부분이 없는지 개발 초기에 Verification(확인)할 수 있습니다.
- 개발 범위(Scope) 산정
    >개발해야 할 기능과 개발하지 않아도 되는 기능(경계 밖)을 명확히 선을 그어주므로 프로젝트가 산으로 가는 것을 막아줍니다.
